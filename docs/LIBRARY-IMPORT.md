# 批量扫描与本地元数据

GameShelf 0.3 的导入流程是：选择目录 → 扫描 → 审核候选 → 修正名称与分类 → 确认导入 → 批量整理。

## 扫描边界

- 扫描只读取用户在系统目录选择器中确认的目录，不写入游戏文件。
- 候选名称来自启动文件、游戏目录或同目录下可选的 `gameshelf.json`。GameShelf 0.3 不连接外部元数据服务。
- 同目录多个可执行文件会作为同一候选的多个启动项。跨目录名称相近的候选只会标记为“疑似同一作品或其他版本”，不会自动合并。
- 已在游戏库中的启动路径默认不可再次选择；名称相近但路径不同的条目交给用户审核。
- 导入确认后，游戏资料在单个数据库事务中写入。扫描发现的本地封面会复制到 GameShelf 受管封面目录；不会移动原图。

## 可选的 `gameshelf.json`

文件必须位于游戏启动文件同级目录，大小不超过 64 KiB。所有字段都可省略：

```json
{
  "title": "Original title",
  "chineseTitle": "中文标题",
  "type": "visual_novel",
  "category": "ADV",
  "contentRating": "general",
  "cover": "cover.png"
}
```

`type` 可选值：`visual_novel`、`rpg`、`simulation`、`action`、`other`。`contentRating` 可选值：`general`、`mature`、`r18`。封面必须是游戏目录内的相对路径；无效字段会被忽略。

本地清单只参与新条目的导入预览，不会覆盖游戏库中已经编辑的名称、分类或封面。

## 整理与封面

导入完成后会直接打开批量整理窗口，可一次设置游玩状态、分类、要加入的合集和安全视图隐私。缺失封面只在批量整理窗口中集中检查，并支持逐项选择替换，不作为游戏库侧栏的独立分类。
