# GameShelf 路线图

GameShelf 的方向是“本地优先的私人游戏藏书馆”。开发重点不是追赶通用启动器的功能数量，而是把本地收藏、隐私、系列整理和正确启动做深。

## 0.2 稳定性（完成）

- [x] 每日自动备份、手动恢复与恢复前完整性/版本校验
- [x] 主进程崩溃日志和不含游戏名称、启动路径的诊断导出
- [x] 事务化数据库版本迁移、迁移前备份与异常退出后的保守恢复
- [x] 游戏进程使用独立进程组和独立标准输入输出句柄
- [x] 启动、备份、恢复和数据目录操作提供可执行的错误提示
- [x] 直接依赖锁定到精确版本，补齐迁移、恢复、损坏库和进程边界回归测试
- [x] Windows 核心稳定性回归与便携预览版生产打包

自动化测试已验证旧库迁移保留数据、无效备份不会覆盖当前库、损坏库可从最近有效备份恢复，以及启动参数要求独立进程。Windows 实机核心回归与 x64 生产打包已经通过；额外故障注入保留为 [补充 Manual 清单](RECOVERY.md)。

完成标准：GameShelf 更新或异常退出不会破坏游戏库，也不会影响已经运行的游戏。

## 0.3 游戏库体验（完成）

- [x] 批量扫描、结果预览、逐项选择与导入确认
- [x] 重复路径、疑似重复游戏、多版本和多启动项识别
- [x] 可审核的启动文件、目录与本地 `gameshelf.json` 名称来源；不联网、不覆盖已编辑条目
- [x] 缺失封面筛选、检查与逐项替换
- [x] 批量编辑状态、分类、合集与隐私设置
- [x] 封面墙和信息列表两种查看方式，长标题完整换行显示
- [x] 扫描 → 审核 → 修正 → 导入 → 整理连续流程
- [x] [Windows 验证批次 A](WINDOWS-VALIDATION-A.md) 核心夹具 12 Pass / 0 Fail

自动化测试使用临时目录验证了本地清单、重复路径、多启动项、跨目录版本提示、批量导入事务与重复回滚；Windows 实机核心夹具 12/12 通过。

完成标准：新增一批游戏后，用户可以在一个连续流程中完成确认、整理和修正。

## 0.4 自有特色（完成）

- [x] Mod 与补丁目录识别；默认只检测
- [x] 启用/停用前 UI 预览、主进程二次确认、带校验备份、同目录原子重命名与变更记录
- [x] 最近一次 Package 变更可按相同安全流程撤销，不删除游戏文件
- [x] 存档路径配置、多个分支和带 SHA-256 清单的快照
- [x] 恢复前校验、自动恢复前快照、同级原目录保留与失败回滚
- [x] 系列合集作品顺序和整体完成进度
- [x] 安全视图从搜索、主页、最近游玩、完成时间线、统计、分类、合集和设置计数中排除隐藏条目
- [x] [Windows 验证批次 B](WINDOWS-VALIDATION-B.md) 修复后 21 Pass / 0 Fail / 1 Skip，junction 独立夹具 Pass

自动化测试在临时目录验证了 Package 备份/双向重命名、快照清单与篡改拒绝、恢复前快照、原目录保留、系列顺序、Package 日志、存档分支和安全视图投影。GS-WIN-001 修复后 Windows 回归通过；跳过的 junction 场景随后由独立 Windows 实机夹具通过。

完成标准：这些能力围绕私人 GalGame 与普通本地游戏收藏形成完整工作流，R18 仍是内容分级而非单独游戏类型。

## 暂不优先

- 云同步与社交功能
- 游戏商店或下载平台
- 多平台支持
- AI 总结与推荐
- 复杂的插件系统
- 角色路线、结局、剧情进度、攻略笔记与剧透边界

这些功能只有在核心本地体验稳定后再评估。
